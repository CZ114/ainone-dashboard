🔁 Workflow JSON 是怎么被执行的？

你的 agent 架构 (Music!!!/project/agent) 原本没有编排层 —— 它是新增的 agent/orchestration/ 子包 (Phase 7, ~300 行)。 核心只有一句话：JSON 不被编译成任何东西，而是被一个解释器逐节点遍历；每个 agent 节点的执行 = 调你原有的 Agent.send()。core 一行没改。

点卡片看「JSON 写法 ↔ 解释器分支源码」的对应。所谓"识别"就是 _run_steps 里的一个 if/elif 分发，没有注册表、没有反射、没有魔法。





④ 三条底层设计（为什么 core 不用改）



  
1 · 解释执行，不编译
spec 永远是 dict。_run_steps 用 Python 的 for/递归/异常实现顺序、循环、跳出 —— JSON 只描述"走哪条路"，控制流全是普通 Python。

  
2 · 鸭子类型边界
引擎对节点的全部要求 = 有 .send(text) → str。节点怎么构造通过 build_agent 注入（dashboard 的 factory 从 agents.json 建），引擎不 import Agent。这和你 Phase 1 留的 approval_callback 是同一个设计哲学。

  
3 · 节点实例缓存 = 记忆
node(name) 闭包每个名字只构建一次。critic 第 2 轮记得第 1 轮，是因为同一个 Agent 实例的 self.messages 在自然累积（你 Phase 1 的历史机制），引擎自己不管理任何对话状态。
