核心理念：角色不是权限开关，是同一事实的三种讲法。同一条工作流事件流、同一路传感器数据、同一篇日记——患者看到"有人在照顾我"的故事，医生看到可审计的临床决策过程，开发者看到带 token 账本的原始机器。下面点角色卡切换，注意三个视角里标着 run_0714_clinic 的地方：那是同一次运行。

① 渲染分级 同一份数据三种镜头，不做三套后端 ② 结构分级 导航/设置页按角色清单生成，不再全员平铺 ③ 权限分级 后端策略表强制 (M2)，前端隐藏只是防误触 ④ 身份归属 本地库 patients.db 登录，patient_id 贯穿三端做数据归属

      实施阶段 · 后端先立门，前端再换镜头

      M0 网络收口 当天 · 3 行

      • 三个后端 (:8100 / :8080 / :3000) 全部绑 127.0.0.1，仅网关对外
      • 立刻消灭局域网直连 MCP / pip 安装的无鉴权 RCE 面

      M1 前端分级+登录 ~1 天

      • rolePolicy.ts 一张功能×角色表 (唯一事实源)
      • 本地库 patients.db (SQLite)：患者=编号+配对码，医生/开发者=账号密码
      • RoleContext + 登录页 + localStorage 记忆登录态
      • Header/Settings/Chat 按表条件渲染，/ 按角色分流
      • 只防误触，不防越权

      M2 后端强制 ~1.5 天

      • 网关统一 authz 中间件：角色×前缀策略表，默认 fail-closed
      • 矩阵覆盖三服务：含 /api/diary/*、/ws/shell (仅开发者)
      • 患者 oneshot/voice 锁死 systemPrompt (防提示覆盖越狱)
      • 开发者角色 PIN→HMAC token 验签；写操作落审计日志

      M3 体验深化 迭代

      • 患者"今天"页 + 呼吸圆环 + 照护丝带
      • 工作流 schema 加 labels.{patient,doctor} 叙事字段 (缺省回退通用文案+开发者告警)
      • 引用依据卡：现有 references 事件扩展进运行归档
      • 会话/日记/录音/运行按 patient_id 归属过滤；审批/human输入记录行为人；run 存定义快照 (审计可复现)

      必须说清楚的三件事

      1. 前端隐藏 ≠ 安全。M1 之后界面上看不到 ≠ 调不到——改一下 localStorage 或直接 curl 就能绕过。真正的门是 M0(绑本机) + M2(后端策略表)。演示原型只展示"看起来的样子"，安全承诺以 M2 落地为准。

      2. 给患者的"人话翻译"是有损压缩。把 agent 输出改写成温和的丝带文案，可能软化医学含义——患者可见的模板文案应由医生角色审定，并常驻"本内容不构成诊断结论"声明。

      3. 现状零鉴权比想象的更宽。调研确认系统有 三个后端、共 60+ 个端点全部无鉴权，其中 MCP 注册和 pip 扩展安装等价于远程执行任意命令。这是本方案把 M0 放在第一天的原因。
      docs/proposals/role-tiered-ui-demo.html — 由多 agent 调研工作流产出（前端 26 单元 + 后端 46 端点盘点 → 双方案独立设计 → 交叉批判）后综合。配色取自应用设置里现成的 nord · 浅色 主题（frontend/src/index.css 227-243 行），落地时患者/医生角色默认主题即设为它。演示原型，未改动任何真实代码。
